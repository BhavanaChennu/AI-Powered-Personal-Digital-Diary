# Deployment Guide — My Digital Diary

Deploying free on **Render** (backend + PostgreSQL) and **Vercel** (React frontend).

---

## Before you start

You need free accounts on:
- [GitHub](https://github.com) — to host the code
- [Render](https://render.com) — backend + database (no credit card)
- [Vercel](https://vercel.com) — frontend (no credit card)

---

## Step 1 — Push to GitHub

Create **two separate repositories**: `diary-backend` and `diary-frontend`.

```bash
cd diary-backend
git init
git add .
git commit -m "Initial commit"
git remote add origin https://github.com/YOUR_USERNAME/diary-backend.git
git push -u origin main
```

Repeat for `diary-frontend`.

**Before pushing, verify no secrets are committed:**
```bash
git grep -i "groq\|password\|secret" -- '*.properties'
```
You should only see `${ENV_VAR:default}` placeholders — never a real key.
The included `.gitignore` files already exclude `target/`, `node_modules/`, and `.env`.

---

## Step 2 — Deploy the backend + database on Render

1. Go to Render → **New** → **Blueprint**
2. Connect your `diary-backend` GitHub repo
3. Render reads `render.yaml` and creates both the web service and the PostgreSQL database automatically
4. When prompted, set these two environment variables:
   - `GROQ_API_KEY` → your key from console.groq.com
   - `FRONTEND_URL` → leave blank for now (you'll fill it in at Step 4)
5. Click **Apply** and wait for the build (first build takes ~5 minutes)
6. Copy your backend URL — it looks like `https://diary-backend-xxxx.onrender.com`

**Verify it works:** visit `https://your-backend.onrender.com/api/diary` — you should get a `401 Unauthorized` (not a connection error). 401 is correct here: it means the server is alive and the security layer is working.

---

## Step 3 — Deploy the frontend on Vercel

1. Go to Vercel → **Add New** → **Project**
2. Import your `diary-frontend` repo
3. Framework preset: **Create React App**
4. Under **Environment Variables**, add:
   - Name: `REACT_APP_API_URL`
   - Value: `https://your-backend.onrender.com/api`  ← your Step 2 URL, with `/api` on the end
5. Click **Deploy**
6. Copy your frontend URL — e.g. `https://diary-frontend-xxxx.vercel.app`

---

## Step 4 — Connect them (important!)

Go back to Render → your backend service → **Environment** → set:

- `FRONTEND_URL` = `https://diary-frontend-xxxx.vercel.app`  (your Vercel URL, **no trailing slash**)

Save. Render redeploys automatically.

Without this step, the browser will block every request with a CORS error.

---

## Step 5 — Test the live app

1. Open your Vercel URL
2. Register a new account
3. Create an entry, try the AI tools

**First load will be slow (~30-60 seconds).** Render's free tier sleeps after 15 minutes of inactivity, and Spring Boot takes time to cold start. This is normal.

## Environment variables reference

### Backend (Render)
| Variable | Purpose |
|---|---|
| `DATABASE_URL` | Auto-filled by Render from the database |
| `DB_USERNAME` | Auto-filled by Render |
| `DB_PASSWORD` | Auto-filled by Render |
| `JWT_SECRET` | Auto-generated by Render |
| `GROQ_API_KEY` | **You set this** — from console.groq.com |
| `FRONTEND_URL` | **You set this** — your Vercel URL |
| `PORT` | Auto-set by Render |

### Frontend (Vercel)
| Variable | Purpose |
|---|---|
| `REACT_APP_API_URL` | Your Render backend URL + `/api` |

## Common deployment errors

**CORS error in browser console**
`FRONTEND_URL` on Render doesn't exactly match your Vercel URL. Check for a trailing slash or `http` vs `https`.

**401 on every request after login**
Usually a stale token from a previous deploy. Log out, clear localStorage, log back in.

**Backend build fails**
Check the Render build logs. Most common cause is a Java version mismatch — the Dockerfile pins Java 17 to match `pom.xml`.

**Blank page on Vercel**
`REACT_APP_API_URL` was set after the build. React bakes env vars in at build time, so you must **redeploy** after changing it.

**Entries load but AI buttons fail**
`GROQ_API_KEY` isn't set on Render, or the model name is outdated. Check `console.groq.com/docs/models` for currently available models and update `GROQ_MODEL`.

## What changed for deployment

- **MySQL → PostgreSQL** — Render's free database is PostgreSQL. JPA/Hibernate handles the dialect difference automatically.
- **Images now stored as base64 in the database** — free hosts wipe the filesystem on restart, so disk-based uploads would lose user photos. Images are downscaled to 900px and compressed before embedding. Videos are capped at 3MB.
- **All secrets moved to environment variables** with local fallbacks, so local development still works unchanged.

---

## Running locally after these changes

You now need PostgreSQL locally instead of MySQL:

```sql
CREATE DATABASE diary_db;
```

Then update `application.properties` fallbacks (or set env vars) to match your local Postgres username/password, and run as usual. Tables are created automatically on first start.
